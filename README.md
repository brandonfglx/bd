## Quick Start
1. Download the latest release builds [here.](https://github.com/brandonfglx/bd/releases/latest)
2. Extract the binary from the downloaded file
3. (macOS only) Open the terminal and remove the app quarantine: `xattr -d com.apple.quarantine bd` (Check [Troubleshooting](https://github.com/brandonfglx/bd/blob/main/README.md#Troubleshooting) to learn more)
4. Launch bd using the terminal: `./bd --help` (Unix)
5. Create a new `bd` project using `./bd init`
6. Now you can create new pages using `./bd add [name]`, build with `./bd build`, and preview with `./bd preview`
7. To publish, you must have [git](http://git-scm.org/) installed. You can download it from your package manager or [the official website](http://git-scm.org/install). Then call `./bd publish` - `bd` may ask you to input the remote repository's URL which should be in HTTP or SSH.

## Features
Commands:
 - init: initializes a new bd directory and scaffolds `templates/`, `static/`, and `.github/workflows/pages.yml`; use `--force` to reset generated defaults,  `--upgrade` to refresh only `templates/` and `static/`, and `--css tailwind` to use TailwindCSS templates
 - add: creates a new page using the local date and prints the UTC offset; use `--tag [TAG]` to add a tag to a page
 - rm: removes a page with the given name; use `--tag [TAG]` to remove a tag from a page
 - build: generates a static build, copying `static/` and applying `templates/` overrides
 - preview: open a small web server to preview `build/` files (use `--port` to set the port)
 - publish: automatically stage, commit, and push changes to the remote repository (use `--page` to only publish a page); use `-m | --message` to add a custom commit message, `--force` to skip version checking, and `--upgrade` to upgrade the blog before publishing

Other:
 - Add tags using `bd add/rm --tag [tag] [slug]` - adds the given tag to the page with the given slug (or change in the page's `page.toml`; add each item as a list of strings)
 - Add custom footer values by modifying the `blog.toml` file with each footer entry starting with `[[footer]]` and containing values for `title` and `url`
 - Easy migration through `bd init --upgrade [dir]` or force clean the entire directory using `bd init --force [dir]` - does not modify user created directories or files (any files generated by `bd` can be modified)

## Technicals
`bd` written entirely in Rust. It leverages multiple dependencies including (but not limited to) clap, toml, serde, minijinja, and pulldown-cmark. These dependencies ensure that `bd` relies on the actual user-facing logic.

Dependency usage:
 - clap - used to parse command line arguments
 - toml - parses TOML for a `bd` project
 - serde - manages serialization and deseralization
 - minijinja - allows dynamic static creation of HTML
 - pulldown-cmark - markdown processor (pages use markdown as main markup language)

## Layout
 - blog.toml - site config (title, description, author, language, build)
 - slug/page.toml - page metadata (title, description, date, draft, tags, content)
 - slug/page.md - page content by default; other files in the page directory are copied as-is
 - templates/ - optional overrides for base.html, index.html, and post.html
 - static/ - copied to the build root (style.css, CNAME, robots.txt, 404.html, etc.)

Template partials may use `.html`, `.htm`, `.jinja`, `.j2`, `.txt`, or `.xml` extensions.

## Build Safety
`bd build` renders into a temporary directory next to the output and swaps it into place. If rendering or writing fails, the previous build (if present) is left untouched.

The output directory contains a `.bd-output` marker. `bd` only replaces a directory that contains this marker, so builds older than `v0.0.2` will need to use `bd build --force` to replace a directory that bd cannot verify that it created.

## Troubleshooting
 - Why does macOS warn me about `bd` being dangerous?
	- macOS has a feature called Gatekeeper that prevents certain binaries to be run if they are not verfied by an Apple Developer account. Since this project is small and I do not have the capability to verify `bd`, you will have to manually remove the quarantine protection using `xattr -d com.apple.quarantine [bd executable]`.
 - How do I publish?
	- Publishing using `bd` requires you to configure a remote repository (another location on the internet) through GitHub (or any other hosting service that supports git) and connect it to your local repository. First, create a GitHub repository then execute `git remote add origin [URL]` (substitute URL for your repository's URL) and then call `./bd publish`.
 - How do I upgrade bd?
	- Since `bd` does not have a self-updater, you must install the latest release from GitHub if it's available. You may need to follow the migration guides below to transfer data.
 - How do I change the blog?
	- Although `bd` has some commands to change your blog's configs, it's recommended to edit the `blog.toml` file in the root of your blog's directory. For example to create a footer:
	```toml
	footer = [
		{ title = "GitHub", url = "https://github.com/brandonfglx" },
		{ title = "Profile", url = "https://brandonfglx.github.io" }
	]
	```
	Or to change the favicon:
	```toml
	favicon = "https://avatars.githubusercontent.com/u/173737496"
	```
 - How do I tag?
	- Use the `add` or `rm` commands with the `--tag` flag to create or remove a tag, respectively. Once created, tags will automatically have their own tag pages built by `bd`.
 - How do I preview my blog?
	- Use the `bd preview` command to start a small static server on your local machine. You can access your blog by entering the URL generated by the command (should have `127.0.0.1`). However, `bd preview` will not dynamically update when a file changes, so you need to run `bd preview` again (`bd preview` automatically builds).

## Migration
Older versions of `bd` relies on older files that may have been changed in a later release. As a result, the `build/` artifacts may be outdated and requires a newer version of `bd` to remedy. Before you upgrade, make sure you create a backup of your projects. To resolve this, install the latest version of `bd` [here](https://github.com/brandonfglx/bd/releases/latest) and add it to your PATH if neccessary. Then use `bd init --upgrade` to refresh the `templates/`, `static/`, and `.github/workflow/pages.yml` directories. Rebuild your `bd` project and use `bd preview` to see the changes.

To force reset all generated files, use `bd init --force`. Be careful: `--force` will reset `templates/`, `static/`, `README.md`, etc., however it will not delete any user created files or directories.
